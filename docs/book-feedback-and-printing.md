## 시작하기

이번 작업은 `wwwiggle/new_wiggle`의 main을 새로 clone한 `C:/Users/user/Desktop/Project/new_wiggle`의 `codex/rubric-feedback-book-orders` 브랜치에 있다. main push와 운영 배포는 하지 않았다.

`npm.cmd install` 후 `.env.example`을 참고해 `.env.local`에 아래 값을 직접 입력하고 `npm.cmd run dev`를 실행한다. 이 작업에서 만든 `.env.local`의 키는 비어 있다. 키는 Git에 넣지 않는다. Vercel에서는 프로젝트 Settings → Environment Variables에 등록하고 재배포한다.

```dotenv
OPENAI_API_KEY=
BOOK_FEEDBACK_MODEL=gpt-5.6-sol
SWEETBOOK_API_KEY=
SWEETBOOK_ENV=sandbox
SWEETBOOK_LIVE_ORDERS_ENABLED=false
```

기존 OpenAI 연결을 재사용한다. `BOOK_FEEDBACK_MODEL`은 계정에서 사용할 수 있는 이미지 입력·구조화 출력 모델로 변경할 수 있다. OpenAI API 키는 https://platform.openai.com/api-keys 에서 발급한다. ChatGPT 구독과 API 결제는 별개다. 키가 없으면 요청을 보관하고 연결 대기를 표시하며 가짜 평가를 만들지 않는다. Claude 키는 이번 구현에 필요하지 않다.

## 선생님 사용 순서

1. 수업실 명단에서 학생 번호·이름을 관리한다. 피드백 화면에서 학년·반을 따로 저장할 필요는 없다.
2. 학생이 그림책을 완성하면 수업실의 완성 그림책 화면에서 확인한다.
3. **피드백 관리 열기**로 이동해 적용된 10개 영역과 전체 배점·AI 프롬프트를 펼쳐 확인한다. 한 권 또는 최대 50권을 선택해 피드백을 만든다.
4. 화면을 열어 두면 한 권씩 처리한다. 화면을 닫아도 요청·완성 결과는 DB에 남는다. 다시 열어 ‘대기 작업 이어서 처리’를 누른다. 실패한 책은 다시 요청한다. 이미 완료한 동일 버전의 책은 재평가하지 않는다.
5. **피드백 관리**에서 학생·책을 고르고 PDF에 넣을 평가 영역을 선택한다. 점수·합계, 종합 의견, 근거 쪽 번호도 각각 선택할 수 있다. 내용 미리보기를 확인하고 개별 PDF 또는 여러 권의 ZIP을 받는다. 같은 평가 기준의 책에는 현재 구성을 한꺼번에 적용할 수 있다. 구성 선택은 이 화면에 머무는 동안 유지한다.
6. 파일명은 `1_홍길동_우리들의 모험_피드백.pdf` 형식이다. 번호가 없으면 생략하고 이름이 없으면 ‘학생’을 사용하며 학년·반은 요구하지 않는다. 동명 파일은 ZIP 안에서 숫자를 붙여 모두 보존한다.

책의 **모든 쪽의 글과 렌더링된 그림**을 함께 평가한다. 영역별 허용 점수와 근거 쪽을 검증하며, 교사 실명·학생 실명은 평가 메타데이터로 AI에 보내지 않는다. 작품 본문에 아이가 직접 쓴 이름은 작품 내용에 포함될 수 있다. 결과는 교사용 AI 초안이며 학생에게 자동 공개하지 않는다. 예시 PDF의 보라색 제목·서술형 교사 피드백을 참고했고 영역별 점수·총점·기준 버전을 덧붙였다. 긴 피드백은 잘리지 않도록 여러 페이지로 나눈다.

## 엑셀만 교체해서 평가 기준 바꾸기

- 피드백 관리 화면 맨 아래의 **현재 기준 엑셀 양식 받기**로 해당 학급의 기준이 채워진 파일을 받는다. **엑셀 양식 미리보기**에서 실제 셀과 수정 위치를 확인하고, 파일의 연노랑 B·C열을 수정한다. 사용법은 파일 안 ‘수정 안내’ 시트에도 있다.
- 수정한 `.xlsx`를 **엑셀 파일 교체**에 넣는다. 해당 학급에 저장되고 다음 요청부터 적용된다. 서버 코드 수정·재배포가 필요 없다.
- 전체 기본값 변경: `config/rubrics/storybook.xlsx`를 새 파일로 바꾸고 배포한다. 학급에서 따로 올린 파일이 있으면 학급 파일이 우선한다.
- 문장 스타일 변경: `config/rubrics/feedback-prompt.md`를 수정한다. 점수표는 프롬프트에 하드코딩하지 않고 엑셀에서 읽어 합친다. 화면에서 실제 합쳐진 프롬프트를 확인할 수 있다.
- 현재 제공된 파일의 `평가` 시트 A/B/C 열 구조를 유지한다. `채점기준 N` 행의 B열이 영역 이름, 바로 아래 행들의 B열이 점수, C열이 설명이다. 영역 추가·삭제, 이름·배점·설명 수정이 가능하며 파일의 총점도 함께 수정한다.
- 파일 최대 2MB, 영역 최대 20개, 영역별 단계 최대 10개다. 잘못된 구조·중복 점수·총점 불일치 파일은 저장 전에 거절한다.
- 파일 또는 프롬프트가 달라지면 평가 버전이 바뀐다. 각 요청은 당시 기준·프롬프트·책 버전을 보관한다. 책을 수정한 뒤에는 새 완성본으로 다시 요청한다.

## 학생 그림책 작업을 함께 보기

수업실 **오늘 수업** 또는 그림책 목록의 **그림책 실시간 보기**를 연 뒤 학생을 선택한다. 학생이 현재 펼친 쪽과 저장한 내용이 자동 갱신된다. 학생이 작업 화면을 닫았으면 최근 저장한 책을 표시한다. 화살표로 다른 쪽을 읽다가 **학생이 보는 쪽 따라가기**로 돌아올 수 있다.

**조언 보내기**는 작성하기 시작한 쪽에 연결된다. 학생 편집 화면의 **선생님 조언**에 표시되며 학생이 **읽었어요**를 누르면 교사 화면에서도 확인된다. 원문을 동시에 고치지 않으므로 학생 저장과 충돌하지 않는다. 최근 조언 8개를 보여 준다. 교사가 별도로 수정할 때는 기존 **그림책 수정**을 사용한다.

선택한 학생만 1초마다 저장 번호를 확인하며 변경된 한 쪽만 내려받는다. 같은 이미지는 다시 받지 않는다. 숨겨진 탭과 **실시간 잠시 멈춤**에서는 상세 확인을 중단한다. 학생 입력은 교사가 함께 보는 동안 멈춘 후 0.5초 또는 연속 입력 최대 2초에 저장된다. 실제 반영 시간은 네트워크·서버 상황에 따라 달라지며 연결 지연 시 마지막 화면이라는 안내를 표시한다.

## 스위트북 API 가입과 실물 제작

사용자가 전달한 영상의 한국어 자막, 특히 20분 이후 API·Live·실물 확인 부분과 공식 문서를 대조했다. 서비스는 **Sweetbook Book Print API**다. 최신 사양은 영상의 예시 숫자를 고정하지 않고 API에서 읽는다.

1. https://api.sweetbook.com/ 에서 파트너 가입 후 Sandbox API 키를 발급받는다. 자세한 API 안내: https://api.sweetbook.com/docs/ .
2. 위 환경 변수에 Sandbox 키를 넣고 `SWEETBOOK_ENV=sandbox`로 테스트한다.
3. 완성 그림책 화면의 **그림책 주문**으로 이동한다. 한 권 또는 여러 권, 판형, 책마다 수량을 선택하고 인쇄 준비를 실행한다.
4. 각 책의 **표지 PDF와 내지 PDF를 내려받아** 글자·이미지·빈 쪽을 확인한다. 첫 번째 쪽만 앞표지로 쓰며, 두 번째 쪽부터 마지막 쪽까지를 내지에 순서대로 넣는다. 뒤표지는 빈 배경이다. 최소 쪽 수에 부족하면 뒤에 빈 쪽을 추가하며 추가 수를 표시한다. 재단·책등·힌지 크기는 계산 API를 사용하고, 원본 판형은 비율을 유지해 안전 여백 안에 배치한다. 레이플랫은 펼침면 PDF 규칙을 적용한다.
5. 학교·학년·반·받을 사람·전화·주소·수량을 입력하고 **운영자에게 제작 요청 보내기**로 제출한다. 한 요청은 한 배송지이며 최대 50종, 책별 1~200부다. 제출하면 원고 사본이 보관되며 교사 화면에서 실제 발주는 실행되지 않는다.
6. 관리자가 `/admin`에서 표지·내지·요청서를 확인하고 **제작사에 원고 준비 · 견적 조회**를 실행한다. 차감 금액·배송지 확인 체크 후 관리자만 발주한다. Live는 실제 충전금을 차감한다.
7. 실제 운영은 스위트북과 이용 조건·사업자 계약·크레딧 충전을 협의해 Live 키를 발급받은 뒤 Vercel Production에 `SWEETBOOK_ENV=live`, `SWEETBOOK_LIVE_ORDERS_ENABLED=true`를 설정한다. 로컬에서 Live 주문은 차단한다.

주문 전송 중 응답이 유실되면 새 주문을 만들지 말고 주문 이력에서 기존 요청을 복구한다. 같은 본문과 idempotency key를 재사용한다. 제공자 보장 시간 경계에 가까운 요청은 자동 재주문을 막으므로 스위트북 주문 내역을 확인한다. 견적은 10분 후 다시 받아야 하고 가격·잔액도 제출 직전에 재확인한다.

## 검증 범위와 운영 전 확인

자동 검증에는 실제 로컬 HTTP·DB·PDF 생성과 **모의** OpenAI/Sweetbook 응답을 사용했다. 전체 쪽 전달, 권한 분리, 기준 변경, 중복 요청, 부분 실패 재시도, 단권·일괄 인쇄, 응답 유실 주문 복구를 검사한다. 모의 응답은 테스트 전용 preload에만 있으며 앱에는 포함하지 않는다.

현재 실제 키가 없어 실제 모델의 문장 품질과 스위트북 Sandbox/Live 접수·실물 색상·제본 품질은 아직 확인하지 않았다. 키 입력 후 Sandbox에서 대표 그림책 1권의 PDF와 주문을 확인하고, Live에서는 먼저 1부 교정을 권장한다. 운영 배포는 사용자가 main 반영 후 수행하며, 저장·이미지 경로가 추가됐으므로 실제 수업 코드로 `scripts/check-deployed.mjs`와 신규 평가·인쇄 경로까지 운영 실측해야 한다.
`scripts/check-book-browser.mjs`는 production build 뒤 Playwright가 설치된 환경에서 `node --import ./tests/harness/register.mjs scripts/check-book-browser.mjs`로 재현한다. 별도 설치 경로는 `BOOK_PLAYWRIGHT_MODULE`로 지정할 수 있다. 이 검사는 모의 제공자와 격리 DB를 사용한다. 기존 QR 입장 화면의 일시적 실패는 2026-09-09 재검증에서 해소됐다. 최신 검증 결과는 current-state.md에 기록한다.

## 외부 PDF 그림책 가져오기·수정

완성 그림책 화면의 **PDF 그림책 가져오기**에서 PDF를 여러 개 선택하고 각 책의 학생·제목을 지정한다. 학년·반은 해당 학급, 번호·이름은 선택한 명단 학생을 사용한다. 파일당 30MB, 가져오기 쪽 수 제한 없이 한 번에 최대 50권이다. 암호가 걸린 PDF는 먼저 암호를 해제한다.

브라우저의 PDF.js가 모든 페이지를 비율 유지·여백 포함 이미지로 렌더링하고 쪽별로 전송한다. Vercel 요청 제한을 넘지 않도록 이미지 한 장당 3.5MB 이하로 제한하며 자세한 스캔은 해상도를 줄일 수 있다. 페이지 크기가 다르면 첫 페이지에 가까운 책 모양에 맞춰 여백을 넣는다. PDF 원본 파일 자체는 서버에 보관하지 않으므로 원본은 별도로 보관한다.

가져오기가 끝난 책은 기존과 동일하게 피드백·주문에 선택할 수 있다. **그림책 수정**에서 기존 편집기로 쪽 추가·삭제·복제·순서 변경, 글·그림 추가, 배경 이미지 교체를 할 수 있다. PDF의 기존 글자와 그림은 하나의 배경이므로 개별 선택·문구 교정은 지원하지 않는다. 그 문구를 바꾸려면 원본 작성 도구에서 수정 후 새 PDF로 가져오거나 수정한 페이지 이미지를 배경으로 교체한다.

수정 후 **완성하기**를 눌러야 피드백·주문 목록에 다시 나타난다. 새 버전은 새 평가와 인쇄 준비가 필요하고 이미 접수한 실물 주문은 변경되지 않는다. 중간에 업로드가 실패한 책은 ‘편집 중인 책’에서 저장된 쪽까지 확인할 수 있다. 실패 파일을 다시 가져오면 새 책으로 시작하므로 중단된 초안과 구분한다. 학생 인증 토큰을 발급하지 않고 교사 쿠키와 담당 학급 권한으로 편집·이미지 접근을 확인한다.

## 관리자와 인쇄 원본 PDF 접수 (2026-09-16)

운영 Google 로그인 이메일 기본값은 `qudcks1940@gmail.com`이다. Vercel 환경 변수 `ADMIN_EMAILS`에 쉼표로 계정을 지정하면 기본값을 교체하며 빈 값은 전부 거부한다. Google OAuth 세션을 사용하고 별도 관리자 비밀번호나 공개 등록 경로는 없다. 로컬 검증 역시 관리자 이메일에 해당하는 교사 세션을 사용한다.

직접 준비한 인쇄 원고는 주문 화면에서 판형/내지 쪽 수를 고른 뒤 크기를 조회한다. 표지는 뒤표지+책등+앞표지 1페이지, 내지는 PUR 한 쪽씩 또는 LAYFLAT 펼침면으로 제출한다. 계산 API가 요구하는 가로×세로 mm를 각 페이지 범위에 표시한다. PDF 모든 페이지를 ±1mm 허용 오차로 검사하고 쪽 수·회전·잘림·기본 단위 변경·손상/암호를 거절한다. 파일당 30MB, 전송당 3MB로 Vercel 본문 한도 내에서 올린다. 원본 PDF를 편집하려면 완성 그림책 화면의 PDF 가져오기 기능을 사용하고 수정 후 새 원고를 제출한다.

규격 출처: [공식 표지/내지 가이드](https://api.sweetbook.com/docs/concepts/pdf-size/). 크기를 하드코딩하지 않고 현재 계정의 계산 API 결과를 사용한다. 페이지 검사 통과는 색상·이미지 해상도·인쇄 미관까지 보증하지 않으므로 관리자가 PDF를 열어 교정한다.

주문 요청서에는 신청 교사/학교/학년/반/수령인/수량/메모와 원고별 규격·실측값이 표시된다. 관리자는 접수 원고와 JSON 요청서를 내려받을 수 있다. 학생 작품을 나중에 수정해도 접수 사본은 바뀌지 않는다. 발주 응답 미확인 시 동일 요청으로 조회하고, 20시간을 넘으면 제작사 포털에서 확인한다. Sandbox와 Live 요청은 섞어 처리하지 않는다.

`/admin`은 10초마다 갱신한다. 학생/교사 heartbeat는 화면이 보일 때 30초마다 보내고 90초 후 만료한다. 여러 탭은 같은 사용자 한 명으로 합친다. 등록 명단 수, 최초 입장자 수, 현재 접속자를 구분한다. CPU/RAM은 로컬 호스트 전체 또는 현재 서버리스 함수만 나타낸다. Vercel 전체 인프라 사용량은 Vercel 대시보드에서 확인한다. 부하 테스트 후 최대 인원과 근거를 입력하면 현재/최대, 추가 여유를 표시한다. 아직 테스트되지 않은 성능을 임의 인원으로 제시하지 않는다.

Git 제출 경로는 최신 사용자 지시대로 `qudcks1940/wiggle_web` 기능 브랜치 → `yonghwan86/wiggle_web` main PR이다. main push·병합은 수행하지 않는다.

## 학생 그림책 편집·완성 (2026-09-23)

글은 책 위 이야기 칸에 직접 왼쪽 정렬로 쓰며 자동 줄바꿈한다. 가득 차면 글자 크기를 줄이거나 다음 쪽으로 이어 쓴다. 학생 완성은 제목 지정과 표지 포함 24쪽 이상이 필요하다. 초안은 빈 제목이어도 저장된다. 그림 비율 유지를 끄면 옆 손잡이로 가로 또는 세로만 늘릴 수 있다. 완성 미리보기에서 첫 화면으로 돌아갈 수 있다.

완성책 목록에서 ‘피드백 관리 열기’를 누르면 평가 기준 엑셀 양식·업로드·피드백 생성·학생별 PDF 구성을 한 화면에서 관리한다. 표지 구분 방식 변경 전 준비한 인쇄 PDF는 ‘인쇄 준비’를 다시 눌러야 새로 받거나 제출할 수 있다. 총 24쪽 책은 표지 1쪽과 내지 23쪽이며 제작 시 내지 끝에 빈 1쪽을 덧붙인다.

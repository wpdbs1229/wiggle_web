# 몽그리 플로팅 카드 — Claude 구현 인계

답변 추가 확인용 시안: [`reference/selected-floating-answer.png`](reference/selected-floating-answer.png). 사용자가 확정한 바탕은 [`reference/selected-floating-base.png`](reference/selected-floating-base.png)의 플로팅 형태다. 화면 속 사과 그림과 세 선택지는 **예시**다. 학생 그림·AI 응답·버튼 글자는 실제 상태와 데이터로 그린다. 시안 전체를 배경 이미지로 사용하지 않는다.

## 사용자 지시와 범위

- 사용자가 고른 것은 세 번째 시안의 **도화지 왼쪽 위 플로팅 카드**다. 아래에서 올라오는 시트가 아니다. 실제 현재 가로 화면은 [`reference/current-floating-1180x820.png`](reference/current-floating-1180x820.png), 최초 선택한 답변 없는 시안은 [`reference/selected-floating-base.png`](reference/selected-floating-base.png)이다.
- 몽그리 캐릭터는 바꾸지 않는다. 기존 `/brand/mongri/curious.png`(질문), `/brand/mongri/listening.png`(답을 기다림), `/brand/mongri/suggesting.png`(다음 행동) 등을 **그대로** 쓴다. 생성된 시안 속 캐릭터를 잘라 앱 에셋으로 쓰지 않는다.
- 질문 카드에서 아이가 **그림 선택지 중 하나를 고르거나 자기 말로 직접 답**할 수 있게 한다. 둘 중 하나만 답으로 제출된다. 답하지 않고 「그리러 가기」로 닫을 길도 유지한다.
- 화면 밖 API 호출·상태·저장 로직을 시안만 보고 추측하지 말고 현재 코드를 확인한다. 이 인계는 디자인과 자산 묶음이며 앱 코드는 아직 수정하지 않았다.

## 파일과 사용법

| 파일 | 용도 |
| --- | --- |
| `assets/crayon-frame.webp` | 투명 중심의 노란 크레용 테두리. 플로팅 카드 뒤에 놓고 `border-image`의 9분할 또는 별도 장식 레이어로 사용한다. 가변 문구를 이미지 안에 굽지 않는다. |
| `assets/name-swash.webp` | `몽그리` 이름 뒤의 노란 크레용 칠. 이름 글자는 DOM. |
| `assets/green-underline.webp` | 질문 아래의 초록 크레용 밑줄. 필요할 때만 보이게 한다. |
| `reference/selected-floating-answer.png` | 질문 + 선택지 + 직접 쓰기 상태의 수정 시안. 사용자 확인 전에는 구현 확정으로 보지 않는다. 구현 이미지로 사용 금지. |
| `reference/selected-floating-base.png` | 사용자가 고른 3번 시안. 새 상호작용을 추가할 때에도 플로팅 위치·느낌의 기준. |
| `reference/current-floating-1180x820.png` | 실제 현행 UI 캡처. 배치와 도구 막대 보존 기준. |

기존 앱 에셋 재사용: `/brand/mongri/*.png`, `/drawing-tools/dock/pencil.webp`(작은 장식에만 사용 가능), 기존 아이콘 컴포넌트. 선택지의 🍎·☀️·⚽는 **AI가 돌려준 `choices`의 `emoji`와 `label` 예시**이며, 사과/해/공을 하드코딩하지 않는다. 도화지 그림도 사용자 작품이므로 예시 그림을 기본값으로 저장하지 않는다.

세 WebP는 원본 투명 PNG를 손실 없이 재인코딩·축소한 장식 파일이다. 모두 alpha가 있고 네 모서리가 완전 투명이다. 접근성 이름·질문·답·버튼은 전부 실제 DOM 텍스트와 버튼으로 둔다. `pointer-events:none`, `alt=""` / `aria-hidden`으로 장식이 입력을 막거나 읽히지 않게 한다.

## 질문 카드의 행동

1. 관찰 한마디(`growthEvent`) → 질문(`question`)을 먼저 보여 준다.
2. `StudentCoaching.choices`의 2~4개 답을 큰 선택 버튼으로 보여 준다. 각 버튼은 이모지 + 짧은 이름이며, 고른 상태는 초록 윤곽 + 체크 + `aria-pressed`로 알린다. 터치 목표는 최소 44×44px, 시안 기준 52px 이상이다.
3. 「내 말로 쓰기」 입력도 항상 보인다. 아이가 선택지를 고르면 입력값을 비우고, 직접 쓰기 시작하면 선택을 해제한다. 공백 답은 제출하지 않는다. 입력은 `maxLength`와 서버 검증 기준을 함께 지킨다.
4. 「이렇게 답할래」는 선택지의 `answer` 또는 아이가 쓴 문장을 하나만 제출한다. 중복 전송·연속 탭·느린 응답에도 상태가 꼬이지 않게 한다. 제출 뒤에는 기존 `nextAction`을 읽기 쉬운 한 줄로 보여 주고 「그리러 가기」로 도화지에 돌아간다. 「다른 것도 물어보기」는 그 뒤에도 접근 가능하게 둔다.
5. ×와 「그리러 가기」는 답을 강제하지 않는다. 자동으로 열린 카드도 같은 탈출 경로를 쓴다.

현재 `product-decisions.md` 학습 과정 25항은 **읽기 전용 카드**로 기록돼 있다. 최신 사용자 요청은 답/선택지 UI를 다시 원한다. 구현 시 문서와 테스트를 함께 갱신한다. 현재 `/api/ai/coaching`의 `action:"answer"`는 `newElements`와 그린 뒤 문서/이미지를 요구하므로, 이것을 즉시 답하기에 그대로 붙이면 안 된다. 먼저 현재 데이터 계약·이벤트 수명·중복 제출을 확인하고 새 흐름에 맞게 설계한다. `StudentCoaching`에는 이미 `choices`가 있다.

## 배치와 반응형

- 가로 태블릿/넓은 화면(현재 CSS 기준 `min-width:900px` 및 `min-height:600px`): 헤더 아래 **왼쪽 위 플로팅 카드**로 유지한다. 현재 도구 막대와 도화지 위에 떠 있으며, 시안처럼 줄인 높이로 그림을 덜 가린다. 좌우 여백과 닫기 위치를 유지하고 도구 막대와 겹치지 않는다.
- 세로 태블릿·휴대전화·낮은 가로 화면: 동일 내용을 좁은 폭에 억지로 압축하지 않는다. 현행 바텀시트 반응형 규칙은 유지하되, 선택지 줄바꿈과 내부 스크롤, 고정 닫기/탈출 행동을 실측해 다듬는다.
- 320×568, 390×844, 844×390, 768×1024, 1180×820에서 실제 DOM 잘림·가로 넘침·도구 접근·연속 탭·키보드 입력을 확인한다. 질문은 길이가 가변이므로 시안의 예시 글자 길이에만 맞추지 않는다.
- 어린이가 쓰므로 글자는 충분히 크고, 선택지의 선택을 색만으로 표시하지 않으며, 직접 입력에는 보이는 이름을 둔다. 장식이 도화지의 포인터 입력이나 확대·도구 조작을 가로채지 않는다.

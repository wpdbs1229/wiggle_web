기준: [DESIGN.md](bmad/planning-artifacts/ux-designs/ux-wiggle-web-2026-08-31/DESIGN.md).
사용자 지시: 첫 화면부터 학생 입장·그리기까지 그대로 유지하고, 그림책 이후 새 화면의 불일치만 정리한다.

## 구현 경계

- `DesignSurface`는 위 후속 경로의 layout에만 둔다. `display: contents`로 기존 레이아웃의 상자를 추가하지 않으며 모든 새 CSS는 `.design-surface`, `.design-student`, `.design-adult`에 한정된다.
- 기존 전역 CSS와 대문/입장/그리기 컴포넌트는 수정하지 않는다. 문서 폰트는 UI에만 적용하고 그림책 본문용 폰트는 PDF와의 일치를 위해 그대로 둔다.
- 교사/관리자의 실명·점수·운영 현황은 이후 사용자 결정으로 추가된 기능이다. 오래된 디자인 문서의 기능 제한을 이유로 제거하지 않는다.
- 버튼은 최소 44px, 교사용 주요 버튼 46px, 학생 주요 행동은 56px 이상. 상태는 문구를 유지하고 선택은 테두리/체크·접근성 속성으로 확인할 수 있게 한다.

## 검증

- 재현: `npm.cmd run build` 후 `node --import ./tests/harness/register.mjs scripts/check-design-system-browser.mjs`. Playwright/Chrome 설치 경로는 `BOOK_PLAYWRIGHT_MODULE`/`BOOK_CHROME_PATH` 환경 변수로 지정할 수 있다.
- 이전 리비전에서 `--baseline`으로 보호 화면의 computed style을 저장하면 변경 후 자동 비교한다. 기준 파일이 없으면 비교 생략을 명시하고 경로 경계만 검사한다. `.design-surface`가 대문/입장/그리기에 나타나면 실패한다.
- 로컬 DB/파일 저장소에 예시 교사·학생·책·작품·피드백을 생성한다. 가족 기록도 로컬 공유 세션을 사용한다. 운영 API/AI/제작사 호출은 하지 않는다.
- 화면별 1440×1000, 320×568, 390×844, 844×390에서 문서 넘침, 도구 글자 잘림, 헤더 버튼 겹침, 피드백 다운로드 줄의 대비, 표시된 활성 버튼의 44px 터치 영역을 확인한다.

# Wiggle Web 확정 제품 결정

> 마지막 갱신: 2026-09-09
> 이 문서에는 사용자가 명확히 확정한 결정만 기록한다. 제안·추측·검토 중인 내용은 `pending-decisions.md`에 기록한다.

## 프로젝트와 제품 중심

1. 기존 Flutter 저장소를 수정하지 않고 `wiggle_web`을 별도 Git·GitHub 저장소로 운영한다.
2. (2026-08-23 확정) 이후 웹 개발은 신규 팀 저장소 `https://github.com/wwwiggle/new_wiggle`에서 계속한다. 기존 `yonghwan86/wiggle_web`은 Vercel 연결을 실제로 바꾸기 전까지 현재 운영 배포 원본으로 보존한다.
3. (2026-08-23 확정) 신규 팀 저장소는 `main`을 기본 브랜치로 사용하고, 현재 검증 브랜치 `codex/updated-design-storybook`을 Pull Request로 `main`에 병합한다. 이후 기능도 직접 `main`에 쌓지 않고 기능 브랜치와 PR 흐름을 사용한다.
4. 제품 중심은 `AI 그림 학습 도구 + 교실 창작 코칭 플랫폼`이다.
5. 이야기·가족 공유·구독은 그림 학습과 교사 코칭 이후 단계적으로 확장한다.
6. AI는 그림을 대신 완성하거나 평가하지 않는다. 부르는 방식은 2026-09-12에 바뀌었다 — 아이가 부를 때에 더해 **몽그리가 먼저 말을 거는 자동 개입**을 둔다(같은 절 6-1항). AI 도우미의 이름은 `몽그리`다(2026-09-07 사용자 결정, 옛 이름 `그리미`). 예외: 완성한 그림책에 대한 **교사용 루브릭 평가**는 2026-09-09 별도 요청으로 두며, 아이 화면이 아니라 교사 화면에만 나온다.
7. 점수·순위·재능 진단·공개 SNS 경쟁은 만들지 않는다. 완성 그림책의 교사용 루브릭 채점·피드백 PDF만 예외다(2026-09-09 사용자 요청).
8. 핵심 학생 대상은 **초등학교 3~6학년**이다(2026-09-12 사용자 정정. 2026-09-09에 1~5학년으로 잡았던 것을 바꾼다). 글을 읽을 수 있는 나이지만 읽기 부담은 낮춘다 — 핵심 행동은 그림·아이콘·큰 터치 영역으로도 알 수 있어야 한다(브라우저 읽어 주기 버튼은 2026-09-09 사용자 지시로 제거).

## 학생 입장과 기록

1. 수업 코드와 학급 QR은 학급 입장 수단이며 학생 신원이나 작품 접근 권한이 아니다.
2. 작품과 과정 기록은 서버가 발급한 익명 학생 ID에 저장한다.
3. 학생 이메일·학교명 없이 참여한다. 학생 실명은 교사가 만든 학급 명단에만 두고 그 학급 담임 교사에게만 보여 준다(2026-09-07 사용자 결정). 이유: 교사가 15명 남짓한 학급을 직접 열고 명부와 대조하려면 부르는 이름만으로는 부족하다는 현장 의견. 학생 화면·가족 공유·그림책·AI 요청에는 실명을 싣지 않으며, 학급을 지우면 명단도 함께 지운다.
4. (2026-09-09 결정, 2026-09-12 개정) **입장은 두 단계다: 반을 정하고 → 아이 참여 코드 네 자리.** 반은 **학급 QR이 기본**이고, QR을 못 쓸 때 대문에서 4자리 수업 코드를 넣는다. 참여 코드는 여섯 자리에서 **네 자리로 줄였다**(2026-09-12 사용자 결정) — 여섯 자리는 저학년이 누르기 벅찼다. 종전 문장은 다음과 같다. ~~입장은 수업 코드 → 아이 참여 코드 6자리, 두 단계다.~~ 교사가 명단을 만들면 자리(번호·실명)마다 무작위 참여 코드가 붙고, 아이는 대문에서 4자리 수업 코드나 학급 QR로 반을 확인한 뒤 자기 참여 코드 하나만 누르면 바로 자기 도화지로 들어온다. 처음 들어올 때만 동물 하나를 고르고, 별명은 그 동물의 기본 별명이 자동으로 붙는다(아이가 글자를 치지 않음). 동물을 고르면 곧바로 빈 도화지가 열린다(학습 과정 0항). 이유: 번호 + 그림 비밀번호 3개는 1~2학년이 매번 기억해야 해서 너무 어려웠다("지금 너무 어려워서 변경할려고"). 코드는 종이에 적혀 있고 코드가 곧 그 아이의 자리라, 다음 회차에 같은 코드를 넣으면 같은 학생 ID로 돌아오므로 아이가 자기 지난 그림을 찾을 필요가 없다.
4-2. (2026-09-13 사용자 결정) **입장 화면 두 곳에 앱 안 QR 찍기를 둔다.**
   - 첫 화면(수업 코드 입력): `QR로 찍기`. 반 QR을 찍으면 그 반 참여 코드 화면으로, 아이별 쪽지 QR을 찍으면 키패드 없이 바로 들어간다.
   - 참여 코드 화면: `내 쪽지 QR로 찍기`. 아이별 쪽지 QR만 쓸모가 있다(반 QR에는 참여 코드가 없다고 안내한다).
   - **쪽지 QR은 아이마다 다르다.** `<반 주소>/join/<수업 코드>#entry=<참여 코드>`. 선생님 화면·전자칠판의 큰 QR은 반 QR 그대로다 — 한 아이 코드를 반 전체에 띄우면 안 된다.
   - 참여 코드는 쿼리가 아니라 **주소 조각(`#`)**에 담는다. 조각은 서버로 가지 않아 접속 로그·Referer에 남지 않고, 입장 화면이 읽자마자 `history.replaceState`로 주소창·방문 기록에서 지운다.
   - 스캐너는 찍은 주소를 따라가지 않는다. 네 자리 숫자 둘만 꺼내 우리 주소로 다시 만든다. 형식이 조금이라도 다르면 거절한다.
   - 이유와 위험: 저학년이 네 자리를 누르기 어렵다. 쪽지 한 장이 입장 수단이라는 점은 종전과 같다 — 같은 쪽지에 참여 코드가 이미 글자로 인쇄돼 있기 때문이다(5항). 코드를 새로 뽑으면 옛 QR도 함께 죽는다(QR이 같은 코드를 담으므로). 무차별 대입은 기존 학급+IP 제한이 그대로 막는다. 사용자에게 "쪽지 한 장이 그 아이 그림을 여는 열쇠가 된다"는 위험을 알린 뒤 결정했다.
4-3. (2026-09-13 사용자 결정) **첫 입장의 동물 고르기는 "나랑 닮은 친구를 골라요" 화면이다. 고른 친구의 이름이 곧 별명이 된다.**
   - 친구 10종과 이름: 토끼 솔이, 곰 보리, 여우 루루, 호랑이 호두, 판다 모모, 강아지 두부, 고양이 나비, 코알라 코코, 사자 해솔, 개구리 초롱.
   - (2026-09-14 사용자: "캐릭터 20종류까지 늘려줘 옆으로 이동할 수 있도록 표시도해주고") 친구를 20종으로 늘렸다. 더한 10종: 펭귄 도리, 햄스터 콩이, 돼지 봄이, 원숭이 미소, 송아지 누리, 양 구름, 기린 키키, 코끼리 다솜, 부엉이 별이, 수달 하루. 화면은 한 쪽에 10종(5×2, 휴대폰 2열)씩 두 쪽이고, 양옆 화살표·아래 쪽 점으로 넘기며 손가락으로 밀어도 넘어간다. 휴대폰은 화살표를 점 양옆으로 내린다. 버튼은 "솔이와 시작하기"처럼 받침에 맞춰 와/과를 붙인다.
   - 서버 기본 별명(`lib/nickname-ideas.ts` 각 동물의 첫 후보)이 곧 친구 이름이다. 화면(`lib/animal-characters.ts`)은 이름을 따로 적지 않고 그 첫 후보를 읽어, 화면과 들어간 뒤 별명이 어긋나지 않는다. 이미 들어온 학생의 별명은 바꾸지 않는다.
   - 같은 반에서 같은 친구를 고르면 별명이 겹친다. 입장은 참여 코드로 구분되고 선생님은 실명으로 보므로 막지 않는다.
   - 화면은 시안(`docs/design-assets/animal-picker/mockup-2026-09-13.png`) 배치다. 동물 그림은 코덱스(사용자 ChatGPT 구독의 Codex CLI 이미지 생성)로 만든 폭신한 3D 인형 10종이다(2026-09-14, 사용자: "너가 직접 코덱스가 구독으로 되어있는데, 그걸 연결해봐라"). 원본은 `codex-assets/`, 화면 파일은 같은 이름의 `public/entry-green/animals/<slug>.webp`. 옆 장식(손글씨·몽그리·크레용 그림)은 카드를 가리지 않는 큰 화면에서만 보이고, 태블릿에서는 숨긴다(Claude 판단 2026-09-14 — 태블릿은 격자 옆 여백이 없다).
5. 참여 코드는 교사 화면(명단·설정 탭, 코드표 인쇄)에만 보인다. 학생 응답에는 번호·이름·코드 목록을 절대 싣지 않는다. 코드 종이를 잃어버리거나 새어 나가면 교사가 그 아이 코드만 새로 뽑고(그림·별명은 그대로), 옛 코드는 바로 죽는다. 코드는 네 자리(만 개)이고 학급 + IP 버킷(60회/10분)이 무차별 대입을 막는다. 여섯 자리보다 추측이 쉬워진 것은 사실이나, 코드는 그 학급 안에서만 통하고 얻는 것은 아이 그림 접근뿐이라 이 한도로 감당한다고 판단했다(2026-09-12). 교사 화면에 그대로 보여 줘야 하므로 해시가 아니라 평문으로 저장한다(수업 코드와 같은 등급의 값).
6. 같은 기기 재접속과 공유 태블릿 학생 전환을 지원한다. 전환은 나가기 뒤 다른 아이가 자기 코드를 넣는 것이다.
7. 메인 화면의 수업 코드와 학급 QR은 모두 학급을 확인한 뒤 같은 참여 코드 입력 화면으로 이어진다. 수업 코드와 QR은 없애지 않는다(2026-09-09 사용자: "이거는 없애면 안돼지않아?").
8. (폐기 2026-09-09) ~~기존 학생은 해당 학급 안에서 `동물 + 별명 + 그림 비밀번호 3개`를 입력해 기존 익명 학생 ID와 작품을 연다.~~ 재입장도 참여 코드 하나다.
9. 다른 공용 태블릿에서 같은 코드로 들어가는 것은 예외 복구가 아니라 정상적인 재입장이다.
10. 학급 학생 전체 목록이나 입장 순서 번호를 학생 식별 수단으로 사용하지 않는다.
11. (폐기 2026-09-07) ~~학생 프로필이 하나도 없는 새 학급은 신규 프로필 생성 화면을 바로 열고…~~ 명단 없는 학급은 "아직 준비 중이에요"에서 멈춘다.

13. (폐기 2026-09-09) ~~기본 재입장 수단은 `동물 + 별명 + 그림 비밀번호 3개`…~~ 그림 비밀번호, 개인 QR 복구, 교사 복구 재발급은 코드와 함께 제거했다. `recovery_credentials` 표는 데이터 보존용으로만 남는다.
14. 그림 별명 후보는 동물별로 10개 이상을 제공한다. 후보는 초등학생이 읽기 쉬운 한글 낱말로 만들고 전체 후보가 서로 겹치지 않아야 한다. 2026-09-09부터 아이는 별명을 고르지 않고 동물의 첫 후보가 자동으로 붙는다(`다른 별명` 주사위는 입장 화면에서 사라졌다).
15. 별명의 띄어쓰기는 표시용으로만 유지한다. 별명은 더 이상 식별 수단이 아니므로(코드가 식별) 같은 반에 같은 별명이 있어도 괜찮다. 교사 화면은 여전히 `같은 별명 있음`을 표시한다.
16. 예외(2026-09-09 사용자 결정): 씨앗 선 커리큘럼의 "친구 그림 보기"를 위해, **같은 학급 안에서 교사가 그 회차를 연 동안만** 반 작품을 이름·번호 없이 그림만 볼 수 있다. 학급 입장 정보만으로 다른 학생 작품을 여는 것은 여전히 불가하고, 작품 소유권·저장 경로는 바뀌지 않는다.

6-1. (2026-09-12 사용자 결정) **몽그리가 먼저 말을 건다.** 종전 원칙 「아이가 호출했을 때만 개입한다」를 바꾼다. 이유: 아이가 「몽그리 부르기」를 스스로 찾는 일이 드물어, 부를 때만 여는 구조에서는 이 역할이 사실상 없는 것과 같았다.
   - **뜨는 때**: 아이가 여덟 획 이상 그렸고, 마지막 획에서 75초가 지났고, 지금 펜이 닿아 있지 않을 때.
   - **뜨지 않는 때**: 도화지를 연 지 2분 안, 도화지가 거의 빈 상태(무엇을 그릴지는 선생님 몫이고 몽그리는 새 소재를 가져오지 않는다), 아이가 직접 부른 뒤 30초 안, 완성·소감 창이 열렸을 때, 저장 충돌이나 선생님이 보고 있다는 표시가 있을 때.
   - **빈도**: 그림 한 장에 자동 두 번까지, 자동끼리 최소 5분 간격. 아이가 직접 부르는 것은 종전대로 제한하지 않는다.
   - **형태**: 화면을 덮는 창이 아니라 옆 패널로 열리고, 아이가 다시 그리기 시작하면 스스로 접힌다. 누가 먼저 말을 걸었는지 카드에 표시한다. **그리는 것을 막지 않는 것이 이 결정의 조건이다.**
   - 안전 규칙(평가·점수·재능 진단 금지, 대신 그리지 않기, 한 번에 한 질문)과 서버 상한은 그대로다. 자동과 수동은 같은 경로를 지난다 — 필터를 우회하는 두 번째 길을 만들지 않는다.

## 캔버스와 입력

1. 패드 사용을 중심으로 펜 입력 모드를 기본값으로 한다.
2. 손가락 그리기는 사용자가 명시적으로 선택할 때만 활성화한다.
3. 펜 모드에서 손바닥과 일반 터치는 그림을 방해하지 않아야 한다.
4. 두 손가락 제스처는 확대·축소와 화면 맞춤에 사용한다.
5. 모두 지우기는 확인 후 한 번에 지우며 한 번의 되돌리기로 복원할 수 있어야 한다.
6. 지우개는 실제 지워지는 범위를 네모 커서로 보여준다.
7. 색상은 갈색·민트색을 포함해 충분히 제공하고 선택한 색의 이름을 표시한다.
8. 선 굵기는 현재 선택된 펜을 다시 누르면 그 펜 왼쪽에 펼쳐지는 드래그 슬라이더로 조절한다(2026-08-30 사용자 변경 결정, 2026-09-07 시안으로 확인). 화면 바깥·다른 도구·Esc로 닫는다. 이유: Freeform식의 좁은 세로 플로팅 도구 레일과 넓은 도화지를 유지하면서 굵기를 바꾸기 위해서다. 이 슬라이더는 떠 있는 레일을 쓰는 넓은 화면(가로 900px·세로 600px 이상)에만 둔다. 휴대전화와 세로가 짧은 화면은 2026-08-18의 5단 점 버튼을 그대로 쓴다 — 좁은 화면에서는 팝오버가 도화지를 가리고 44px 터치 목표를 깨기 때문이다. 점은 현재 선택한 색으로 칠하고 지우개 선택 시에는 잉크색으로 남긴다.
9. 도화지는 화면을 가득 채운다(2026-09-07 사용자 결정). 새 작품은 첫 획을 긋기 전까지 그릴 수 있는 넓이의 비율을 따라가고, 한 획이라도 그으면 그 비율로 굳는다 — 그린 뒤에 비율을 바꾸면 이미 그린 선이 늘어난다. 이유: 그리기 화면 시안의 넓은 도화지를 그대로 쓰기 위해서다. 비율은 문서에 함께 저장하며, 세로 값이 없는 기존 작품은 예전처럼 정사각(1024×1024)으로 남는다 — 좌표가 x·y 모두 0~1로 정규화돼 있어 비율을 바꾸면 이미 저장한 아이 그림이 찌그러지기 때문이다. 점선·시범 안내 좌표는 정사각 기준으로 그려 둔 것이라 도화지 가운데의 정사각 영역 안에 넣어 동그라미가 타원이 되지 않게 한다.

## 그림책 만들기

1. 외부 Canva 편집 화면을 붙이지 않고 Wiggle 안에서 직접 동작하는 그림책 편집기를 사용한다(2026-08-20 사용자 결정).
2. 각 쪽의 이야기 글은 하나만 두며 페이지 위쪽 가운데의 고정 영역에서만 편집한다. 글 요소를 추가·복제·이동·회전하는 기능은 제공하지 않는다(2026-08-21 사용자 결정). 이유: 초등학생이 글 배치를 따로 조정하지 않고 이야기 작성에 집중하게 한다.
3. 학생의 완성 그림과 새 그림은 글 아래의 지정된 그림 영역 안에서만 추가·이동·크기 변경·회전할 수 있다. 그림과 선택 박스는 같은 종횡비를 유지하고 지정 영역 밖으로 나갈 수 없다(2026-08-21 사용자 결정). 원본 이미지의 흰색·투명 빈 캔버스는 선택 박스에 포함하지 않고 실제로 보이는 그림의 픽셀 경계에 맞춘다. 원본 자산은 보존하고 요소별 내용 경계를 저장하며, 자동 계산과 `빈 여백 없이 맞추기`를 함께 제공한다(2026-08-23 사용자 결정).
4. 사용자가 올린 배경 이미지는 페이지 전체를 채우는 배경층이 되며, 그 위에 고정 이야기 글과 그림이 올라간다. 배경색은 이미지가 없거나 투명한 부분의 바탕으로 유지한다(2026-08-21 사용자 결정).
5. 그림책은 가로·세로·정사각형 세 가지 비율을 제공한다. 새 그림책을 만드는 모든 진입 경로에서는 편집기를 열기 전에 세 모양 중 하나를 먼저 고르고, 편집 중에도 비율을 바꿀 수 있다(2026-08-21·2026-08-23 사용자 결정).
6. 그림의 이동·크기 변경·회전·스냅 상호작용은 MIT 라이선스의 `react-moveable`을 사용하고 라이선스 고지를 저장소에 둔다. 그림책 문서와 이미지 소유권·저장은 Wiggle의 학생 세션, Turso, R2 경계를 그대로 따른다.
7. 편집기는 페이지 추가·복제·순서 이동, 그림 앞뒤 순서·잠금·투명도, 실행 취소·다시 실행, 캐릭터 배경 오리기, 미리보기와 저장을 제공한다.
8. 학생 홈의 확정된 3개 큰 메뉴 순서는 유지하며, 그림책 작업실은 그 아래의 별도 그림책형 카드와 완성 작품 상세의 `이 그림으로 그림책 만들기` 행동으로 진입한다.
9. 그림책 목록·진입·편집 화면은 **책 팀 소유**다(2026-08-31 범위 명시).
   기존 `종이·나무·하늘색 디자인 계승` 문구는 책 팀이 새 DESIGN.md 채택 여부와 함께 재검토한다 —
   아크 팀의 DESIGN.md가 이 영역을 일방적으로 구속하지 않되, 하늘색 1차색은
   새 시스템의 `파랑 1차색 금지`와 충돌함을 책 팀에 전달한다.
10. 학생이 그림책에서 `완성하기`를 누르면 그 학급의 교사는 완성 그림책 목록에서 동물·별명, 완성 시각, 쪽 수를 확인하고 책 전체를 넘겨 보거나 브라우저 인쇄의 `PDF로 저장`을 사용할 수 있어야 한다(2026-08-27 사용자 결정).
11. 교사는 완성 그림책을 체크박스로 여러 권 골라 한 번에 피드백을 요청하거나 한 권씩 요청할 수 있다. 루브릭이 확정되기 전에는 AI 피드백을 임의 생성하지 않고 요청만 `루브릭 대기` 상태로 보존한다(2026-08-27 사용자 결정).

## 교사와 메시지

1. 교사는 전체 학급 또는 특정 학생에게 텍스트 도움말을 보낼 수 있다.
2. 학생은 닫은 교사 메시지를 다시 확인할 수 있어야 한다.
3. 교사가 학생 작품을 보고 있을 때 학생 화면에 이를 알린다.
4. 음성은 후속 단계이며 텍스트를 기본 수단으로 유지한다. (2026-09-09 사용자 지시) 학생 화면의 브라우저 읽어 주기(들어 보기) 버튼은 전부 제거했다. 교사 목소리 귓속말은 (2026-09-14 사용자: "음성 귓속말 기능 코드는 아예 제거해줘") API·검증·학생 표시·릴레이 연결까지 코드째 지웠다. 외부 중계 서비스가 필요했고 기본값이 꺼져 있어 쓰인 적이 없다.
5. (2026-09-14 사용자 결정) 선생님이 그리는 중인 아이 도화지에 관여하는 방식은 자유 채팅이 아니다. 선생님 표시(동그라미·화살표·짧은 글)는 점선·시범처럼 아이 원본 그림과 **따로 된 층**에 올리고 저장 그림에 합성하지 않는다. 사용자: "1번은 따로 된 층을 추천해주고". 이유: 3~6학년이 글자를 치면 그리기가 멈추고, 선생님 한 명이 여러 대화를 동시에 잇기 어렵고, 그림 조언은 위치를 가리켜야 전달된다. 제안 순서는 ① 원본 크기 거의 실시간 보기 ② 따로 된 층 표시 ③ 아이는 큰 버튼으로 답하기 ④ 아이가 먼저 손들기. 네 가지 모두 2026-09-14에 만들었다. 운영 규칙: 아이 화면에는 답하지 않은 최신 표시 하나만 뜨고, 완성한 그림에는 보내지 않는다. 손은 표시·그 아이 메시지·선생님 손 내리기·아이 스스로 내리기로 내려가고 10분 지나면 사라진다(Claude 판단 — 필요하면 사용자와 조정). (2026-09-14 사용자: "1번으로 진행해줘") 실시간 보기 지연은 선생님이 보고 있을 때만 줄인다 — 아이 자동 저장을 멈춘 뒤 0.5초·길어도 2초, 선생님 확인을 1초로. 보지 않을 때 저장 간격은 그대로다. 새 선만 따로 보내기·실시간 연결은 교실에서 느리다고 느낄 때 다음 단계로 둔다.
7. (2026-09-14 사용자: "첫번째 시안대로 가자") 선생님 화면을 처음 불러오는 동안은 코덱스 시안 1(`docs/design-assets/teacher-loading/loading.png`)대로 실제 머리 줄(로고·학급 목록)과 학급 이름·버튼·탭·학생 그림 카드 8장의 회색 뼈대, 작은 원형 표시와 "학급을 불러오고 있어요"를 보인다. 시안 2(가운데 "이 학급을 열 수 없어요" 카드)는 쓰지 않았다. 대신 첫 응답이 실패하면 끝없는 로딩이 되지 않도록 같은 안내 줄을 서버 오류 문구와 [학급 목록으로][다시 시도]로 바꾸고 뼈대는 멈춰 흐리게 둔다(Claude 판단 — 시안 1만으로는 403이 끝없는 뼈대가 된다).
8. (2026-09-14 사용자: "1 조용한 버튼 + 완성 강조 … 이게 좋네") 그리기 화면 머리 줄 오른쪽 버튼 묶음은 코덱스 시안 1(`docs/design-assets/studio-header-actions/1-quiet-ghost.webp`)이다. 과정 보기·선생님·선생님 말씀은 테두리 없는 선 아이콘+글자, 몽그리 부르기만 연노랑 바탕에 몽그리 얼굴, 완성만 진초록. 이모지 아이콘을 쓰지 않고 편지함에도 "선생님 말씀" 글자를 붙인다. 손 든 상태는 연초록 "손 내리기", 안 읽은 말씀은 연노랑 바탕 + 빨간 수. 휴대폰 세로는 네 버튼을 둘째 줄에 아이콘 위·글자 아래로 두고 완성은 첫 줄에 남긴다. 가로로 눕힌 좁은 휴대폰은 한 줄에 아이콘만 둔다(Claude 판단 — 높이가 낮아 두 줄이면 종이가 너무 작다).
9. (2026-09-14 사용자: "그리고 도구는 B안으로 진행해줘") 그리기 도구는 코덱스 시안 B(`docs/design-assets/studio-tool-dock/B-crayon-box.webp`) — 모든 화면에서 화면 아래에 떠 있는 크림색 도구 막대 하나. 되돌리기·다시하기, 세워진 연필·크레용·마커·수채붓·지우개·좌우 대칭(나비), 색, ⋯ 더보기. 고른 도구는 진초록 바탕에서 올라오고, 붓 끝·띠는 지금 색으로 칠한다. 고른 도구를 한 번 더 누르면 굵기 5단이 뜬다(예전 슬라이더 대신). 막대에는 자주 쓰는 8색+무지개(12색 창 → 색 더보기 대화상자), 폭 900px 아래·낮은 가로 화면은 지금 색 버튼 하나+무지개. ⋯ 안에 채우기·도형·글씨(도형·글씨는 옵션을 이어 고르도록 창을 열어 둠)·펜/손가락 모드·전체 지우기. 휴대폰 세로는 도구 줄 아래 되돌리기·색·더보기 줄, 낮은 가로 화면은 한 줄. 막대가 도화지를 가리지 않게 그 높이만큼 아래를 비운다. 시안의 "스티커" 표기는 실제 기능(좌우 대칭)으로 바로잡았다. 작은 화면에서 몽그리 판은 예전처럼 막대를 덮는다(Claude 판단 — 막대 위로 올리면 좁은 화면에서 도화지가 사라짐).
10. (2026-09-15 사용자: "굵기 5단계 점 … 이런것보다는 상세 픽셀단위로 드래그할 수 있는게 좋은데") 9항의 굵기 5단을 바꾼다. 고른 도구를 한 번 더 누르면 뜨는 창에서 1~60픽셀(1024 도화지 기준 정수)을 끌어 고르고, 옆에 −·+ 1픽셀 버튼과 지금 굵기 점·숫자를 둔다. 저장 형식도 5개 값 목록 대신 1~60 정수를 받는다 — 예전 값(3·8·16·30·48)이 범위 안이라 옛 작품은 그대로 열린다. −·+와 상한 60은 Claude 판단(손끝으로 1픽셀을 맞추기 어렵고, 예전 최대 48보다 조금 넉넉하게).
11. (2026-09-15 사용자: "일단 과정 보기는 제거해주고") 그리기 화면 머리 줄의 과정 보기 버튼을 뺐다. 8항의 버튼 묶음은 몽그리 부르기·선생님·선생님 말씀·완성이다. 과정 기록 저장과 가족 보기의 과정 재생은 그대로 둔다(Claude 판단 — 지시가 그리기 화면 버튼을 가리킴).
12. (2026-09-15 사용자: "도화지는 항상 어떤기기 든지 화면을 꽉채우게 만들어줘") 도화지는 머리 줄 아래를 여백 없이 끝까지 채우고, 도구 막대는 도화지 위에 뜬다(9항의 "막대 높이만큼 아래를 비운다"를 바꿈). 새 작품의 세로 범위를 320~2240(가로로 눕힌 휴대폰 약 3:1 ~ 세로 휴대폰 약 1:2.2), 1 단위로 넓혀 휴대폰 세로·가로에서도 빈틈이 없다. 한 획이라도 그은 작품은 비율이 굳어 있어 모양이 다른 화면에서 열면 가운데 놓인다 — 늘리면 선이 찌그러지고, 비율을 바꾸려면 이미 그린 그림을 옮기거나 잘라야 해서다(Claude 판단). 막대를 도화지 위에 띄운 것도 Claude 판단이다 — 막대 자리를 비우면 막대를 접어도 도화지가 커지지 않는다.
13. (2026-09-15 사용자: "확대 축소 기능을 추가해주고") 도화지 오른쪽 위에 확대(+)·지금 배율(누르면 화면 맞춤)·축소(−) 단추를 둔다. 1.5배씩, 1배~4배. 두 손가락 벌리기, 트랙패드 벌리기(ctrl+휠, 커서 자리 기준), 확대한 동안 스크롤로 옮기기도 된다. 1배 아래로 줄이지 않는 것은 Claude 판단(도화지가 이미 화면을 채운다).

7-1. (2026-09-12 사용자 요청) 명단은 **엑셀(.xlsx)·CSV 파일로도** 넣을 수 있고, **엑셀 양식을 내려받아** 채운 뒤 올릴 수 있다. 양식은 읽는 코드와 같은 자리에서 만들어 규칙이 어긋나지 않게 한다. 파일은 교사 브라우저 안에서만 읽고 서버로 보내지 않는다 — 실명이 든 파일이기 때문이다. 읽은 결과는 입력칸을 채울 뿐이고, 번호·이름 규칙과 저장은 손으로 적을 때와 똑같은 경로를 지난다. 제목 줄은 건너뛰고, 번호가 없으면 1번부터 붙인 뒤 무엇을 했는지 교사에게 문장으로 알린다. 옛 `.xls`는 읽지 않는다.
7-2. (2026-09-12) 참여 코드표는 **브라우저 인쇄**로 나간다. 팝업 창을 새로 열지 않는다 — 1장은 실명이 있는 선생님 보관용, 2장은 잘라 나눠 줄 쪽지(반 QR·수업 코드·내 참여 코드)다.
7. 교사가 학급을 만들 때 명단(번호 + 실명)을 직접 입력하고, 만든 뒤에도 학생을 추가·제거할 수 있다(2026-09-07 사용자 결정, P-001 확정). 학생은 수업 코드나 학급 QR로 들어와 ~~자기 번호를 입력하고 그림 비밀번호로 본인을 확인한 뒤~~ 자기 참여 코드 6자리를 넣고 자기 창을 연다(2026-09-09 변경, `학생 입장과 기록` 4번). 명단은 학생 화면에 보여 주지 않는다 — 수업 코드를 아는 사람에게 반 전체 실명이 노출되기 때문이다. 명단·설정 탭은 자리마다 참여 코드를 보여 주고 복사·새로 뽑기·코드표 인쇄를 제공한다.
8. (2026-09-07 확정) 자기 등록 입장 흐름 — `새로 시작하기 / 내 그림 이어가기` 갈림길, 별명·동물로 프로필을 찾던 재입장, 중복 프로필 허용(`allowDuplicate`) — 은 **대체가 아니라 제거**다. 명단이 없는 학급에서 아이가 스스로 프로필을 만드는 예비 경로를 남기지 않는다. 이유: 두 경로가 공존하면 같은 아이가 명단 자리와 자기 등록 프로필 둘로 갈라져, 교사 화면의 번호와 실제 작품 주인이 어긋난다. 명단이 아직 없는 학급의 학생 화면은 "아직 준비 중이에요"에서 멈추고 선생님을 부르게 한다(`NO_ROSTER`).
9. 교사 학급 상세는 **오늘 수업 / 작품·그림책 / 명단·설정** 세 탭으로 나눈다(2026-09-09 사용자 선택). 오늘 수업은 현재 회차 학생 그림을 큰 썸네일 격자로 보여 주고 회차 변경·수업 안내·전체 메시지만 상단 행동으로 둔다. 작품 탭은 학생·회차 필터와 완성 그림책 진입을 맡고, 명단 탭은 학생 추가·수정·삭제/복원과 입장 코드·QR·가족 링크·학급 삭제를 맡는다. 이유: 수업 중 확인과 평소 관리 행동이 한 화면에 섞여 있던 복잡도를 줄이기 위해서다.
10. 오늘 수업의 학생 그림은 현재 학급에 열린 회차와 같은 `arcId + episodeId` 작품만 표시한다. 회차가 없을 때만 학생별 최근 작품임을 화면에 명시한다(2026-09-09 사용자 선택을 구현하며 확정). 다른 회차에서 나중에 저장한 그림을 오늘 그림으로 보이면 교사가 현재 수업 상황을 잘못 판단하기 때문이다.

## 배포 원칙

1. 기존 Flutter 저장소에는 변경을 만들지 않는다.
2. (2026-08-18 확정) 배포 체계를 전환한다: 개발은 로컬 폴더 → GitHub push → **Vercel 자동 배포**. ChatGPT Sites와 Codex 독립 검증 게이트는 전환 완료와 함께 은퇴한다. 이유: Sites 프록시 의존(SIWC 헤더 인증)이 이전 불가였고, git push 자동 배포로 반복 속도를 올린다.
3. (2026-08-19 확정) 운영 데이터는 이전하지 않고 **신규 시작**한다. 기존 Sites와 그 데이터는 보존해 가역성을 남기고, 폐기는 사용자 명시 승인이 필요하다. 이유: 실사용 데이터가 소규모(작품 32개)였고 서버가 빈 DB에서 자가 프로비저닝된다.
4. (2026-08-18 확정) 스택은 Next.js + Turso(libSQL) + 기존 R2(S3 API), 교사 인증은 구글 OAuth 자체 구현이다. 호스트 중립 어댑터로 다른 호스팅 이전 시 재공사가 없어야 한다.
5. (2026-08-19 확정) 공개 주소는 무료 서브도메인 `https://wiggleweb.vercel.app`으로 시작한다. 유료 도메인(`wiggleweb.app`)은 실사용이 자리 잡으면 구매를 검토한다.
6. GitHub `main` push(=운영 배포)는 사용자가 직접 실행한다. 에이전트는 기능 브랜치 커밋·push까지만 준비한다.
7. (2026-08-20 확정) Local/Test, Vercel Preview, Production은 사용자가 요청한 같은 기능 코드를 공유한다. 환경별 코드 복사본을 만들지 않고 인증·DB·파일 저장소·시드·비밀값만 중앙 환경 경계에서 선택한다. Local/Test는 원격 운영 자원을 사용할 수 없고, Preview와 Production은 서로 분리된 Vercel 환경 변수와 데이터 자원을 사용한다. 로컬 전용 코드는 `dev-only`, 환경 판별은 `runtime` 디렉터리로 명확히 격리한다. 이유: 로컬 검증 결과를 Preview와 운영에 그대로 승격하면서도 테스트 데이터나 자격증명이 환경 사이에 섞이는 사고를 막기 위해서다.
